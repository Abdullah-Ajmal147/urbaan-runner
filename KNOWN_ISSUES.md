# Known issues

| # | Issue | Impact | Workaround / owner decision |
| --- | --- | --- | --- |
| K1 | **Unity 6000.3.25f1 batchmode sometimes hangs during shutdown** on this Linux machine, after it has finished its work and logged its result (`Exiting with code N` / `UR_BATCH_EXIT N`). It started once an emulator was running. Killing adb, the ILPP runner or the shader compiler did not release it, and ptrace is restricted, so no stack trace is available. | Raw `Unity -batchmode -runTests` commands from HANDOVER §8.3 can block forever. | `tools/env.sh` and `tools/env.ps1` (`ur_unity` / `Invoke-Unity`) read Unity's own verdict from the log and stop the process 90 s later if it is still alive. A run that never reports a verdict still fails, via the 45 min timeout. Always use the tools scripts. |
| K2 | **Firestore rules can't fully protect the economy** (HANDOVER §7.1). A modified client can still write plausible values within the rule limits. | Cheating is possible on a rooted device. | Needs server-side validation and purchase verification (Cloud Functions, Blaze plan: owner task 12), planned for a later phase. |
| K3 | **Anonymous accounts are tied to the install.** Uninstalling the app or clearing its data creates a new anonymous user, so the cloud copy of the old profile can't be reached any more. | A player who reinstalls starts from zero. | Account linking (Google Play Games or Google Sign-In → `linkWithCredential`) is a later phase. It needs the owner's Firebase project and OAuth setup (§12). |
| K4 | **The cloud merges with "max", not "sum"** for runs and best distance (there's no server to count runs from two devices). The balance follows the most recently saved device. | If two devices play offline at the same time, the device that syncs last decides the balance; best distance and owned items are never lost. | It's acceptable with one device per player. A server-side ledger fixes it (same later phase as K2). |
| I5 | **Likely fixed (2026-10-06):** this is Unity's generic error when its startup is disrupted. It was reproduced when our Hybrid Composition "kick" paused Unity while it was still starting ("Timeout (2000 ms) while trying to pause the Unity Engine"). The kick now only gives focus: 4/4 cold starts clean with animations on and off. **Original note:** Unity "Not enough storage space to install required resources" dialog, seen once on the emulator after the emulator itself crashed during an install. The device had 6.1 GB free; a clean reinstall worked, and killing the app during Unity's first load recovers fine (tested). | One occurrence, not reproducible. | Watch for it on real phones; if it shows up, catch the state and offer reinstall guidance. |
| I7 | **One ANR in 15,000 random monkey events**, inside Unity's own volume listener (`com.unity3d.player.AudioVolumeHandler`) while the app was being frozen in the background. Replaying the same seed and another seed: 0 ANR, 0 crashes. | Intermittent, not reproducible. | Track it in Play Console vitals after launch. |
